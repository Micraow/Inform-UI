# Skill addition: color, icon, and image composition

Read the installed/generated profile contract before authoring. The exact `Icon` signature is `Icon(name, label?, tone?, size?)` where the name comes from the pinned official catalog, the label may be null for decoration, tone is one of default/muted/info/success/warning/error, and size is 16/20/24/32/48. Older runtimes may not support the trailing arguments or info; verify the selected profile rather than assuming compatibility.

For a visual answer:

1. Start with a useful hierarchy: one main heading, short explanation, content grouped by meaning, and a clear next step.
2. Use a real supplied or original licensed image when it helps explain the answer. Include meaningful alt text. Never use a private reference screenshot as published sample artwork. Do not inflate a one-pixel fixture into a “logo.”
3. Choose a canonical official glyph by purpose from `src/icons/catalog.json`; inspect it in the gallery when appearance matters. Treat catalog categories/aliases as Inform UI metadata, not official classifications.
4. Keep most content neutral. Apply semantic color to a true state, a short notice, or a meaningful glyph. Pair it with readable wording. Select explicit theme-aware role parameters rather than raw color values.
5. In image/text/action combinations, use `Card`, `Stack`, `Row`, and responsive `Grid`; keep a media region distinct from text and action regions. Use 24px icons with ordinary section headings and 32px only for a feature introduction. Large clickable panels need card geometry, not circular button geometry.
6. Make interactions change actual local bindings: a selection changes the displayed content, a checkbox changes completion, a saved state follows a local action. Do not describe local preview changes as a service action.
7. Use `Icon("CheckCircle",null,"success",24)` beside `Badge("Saved locally","success")` to avoid duplicate screen-reader output. Use a label for a meaningful standalone glyph.
8. Verify light/dark, long text, narrow width, keyboard navigation, focus visibility, and that the final generated prompt/schema agrees with the demonstrated API. Source-derived colors are not a blanket contrast guarantee.

Source ownership language: OpenAI Apps SDK UI provides the pinned, MIT-licensed glyph geometry and public primitive/base-role references. Inform UI supplies composition, semantic assignments, accessibility substitutions, host-observation boundaries, and the runtime. Do not imply full private OpenAI UI fidelity.

Runnable source patterns are generated by `createDesignExamples(embeddedLicensedImage)` in `showcase-next/design-examples.mjs`. Use those examples with the actual renderer and expose their editable DSL in the showcase.
