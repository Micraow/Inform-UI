# Supplied automation views

Three independently implemented finite views: `display-automation`, `list-automations`, and `automation-plan-summary`. They display authored data. They do not create, list, edit or cancel real scheduled tasks, resolve accounts, fetch data, navigate, log impressions or infer schedule/time-zone meaning.

## Data and visible behavior

All accept a nonblank accessible `label`, optional `id`, `disabled`, and `status` (`resolved` by default, `pending`, `failed`). Pending renders an accessible loading block. Failed renders supplied `fallback`, or hides the component. Unresolved records cannot contain active item/step data.

- Display: `item` has `id`, `title`, `scheduleLabel`, safe `url`, optional `emoji` and `disabled`. One full-width task card presents those exact strings.
- List: `headerLabel`, `emptyLabel`, finite `items` (maximum 100), optional `viewAll: {label,url}`. Shows the first five items; the footer is a supplied local intent, not a loaded second page. Empty lists display `emptyLabel`.
- Plan: `title`, `goalLabel`, `steps` and `statusLabels` are required in resolved state. Each step has unique `id`, title, and `completed`, `in_progress` or `pending` status. `steps: null` requires `summaryErrorLabel`; empty steps use supplied `emptyLabel` or “No steps”. No completion is inferred.
- Chat plan: two or more completed steps form a disclosure group. Remaining visible steps start at the first in-progress step, exclude completed steps, and are capped at five (`mobile: true`: three). `completedExpanded` supplies initial disclosure state. `completedCountLabel` and `showCompletedLabel` customize labels.
- `showPlanLabel` and `hidePlanLabel` together enable whole-plan collapse. `collapsed` supplies initial state. `layout: library` renders all steps in supplied order without disclosure. `planType: language_learning` numbers unfinished steps and omits whole-plan collapse. Initially collapsed library/learning layouts are rejected.

This is an explicitly supplied `mobile` mode, not an automatic viewport data-selection policy. CSS still adapts to narrow widths. Visual geometry is original; no native/pixel parity is claimed.

## Local actions

Real button activation supports native keyboard semantics. The following events bubble, are cancelable, non-composed, and contain frozen detail objects:

- `iui:automation-open`: `{id, automationId, url}`; `id` is the node ID or null, `automationId` is the item ID or null for the footer. There is no default navigation or remote effect.
- `iui:automation-toggle`: `{id, section, expanded}`, where section is `plan` or `completed`. Preventing default preserves current disclosure. Accepted events change local presentation only.

Controls honor supplied disabled state, current native/ARIA disabled state, disabled fieldsets including the first-legend exception, hidden/inert composed ancestry, event cancellation and permanent ownership retirement. A local admission gate blocks constructor reentry. Update/dispose during event construction or dispatch wins over stale work; ordinary errors remain observable. Form reset restores initial disclosure after cancellation and pending-reset reconciliation. Replacements reset local presentation to the newly supplied defaults.

## Integration and evidence

Domain installer: `installAutomationSchema({node,defs})` from `scripts/automation-schema.mjs`; registers the three nodes in the base schema group. Semantic validation: `inspectAutomation(node,path,add,isSafeURL)`. Renderer: `renderAutomation(context,node)`. Include `automation.css` in renderer embedded styles and the build's standalone stylesheet. The shared owner, generation, intent gate, painter and native-reset helpers are reused; no second resource registry exists.

Domain code is tested with temporary generator, core dispatch, renderer dispatch/style and build-CSS wiring. These shared-file changes are deliberately excluded from the domain-only commit and must be integrated serially before use. Generated schemas/declarations/validator are regenerated by the integrator. A domain-only commit by itself does not register or render a public node.

Tests cover resolved/pending/failed/empty data, validation, five-item list, chat/mobile/library/learning plan behavior, cancellation, reset, supplied disabled and fieldset gates, constructor reentry/error/update/dispose, stale ownership, compiled artifact behavior and replacement. `tests/browser/automation.spec.mjs` defines native Enter/Space, reset, cancellation, update/dispose and narrow-width checks; discovery alone is not execution. Native browser and pixel acceptance remain unverified until separately run.

Native reset anchors to the always-visible whole-plan header toggle when it
exists. The completed toggle inside a hidden plan body cannot veto that reset;
completed-only layouts continue to use their visible completed toggle.
